# Interview Talking Points

Use these talking points when discussing the project in interviews.

## Short Explanation

I built a Claude-compatible GRC skills library to demonstrate how governance workflows can be turned into repeatable, testable, AI-assisted systems.

## Why I Built It

I wanted to show that governance is not just policy writing. Strong governance requires repeatable workflows, evidence expectations, decision logic, escalation paths, and audit-ready outputs.

## What It Demonstrates

- Ability to design structured GRC workflows
- Understanding of change management and CAB governance
- RCA and corrective action analysis
- Audit evidence quality review
- Vendor risk and AI governance awareness
- Framework mapping to ISO 27001, SOC 2, NIST CSF, and COBIT
- Practical use of GitHub Actions for validation and packaging
- Ability to create portfolio-ready technical documentation

## Strong Interview Answer

This project demonstrates Governance Systems Engineering. I took common GRC workflows and converted them into reusable Claude-compatible skills with tested outputs. Each skill is designed around a real practitioner scenario, such as reviewing a change request, assessing RCA quality, preparing audit evidence, or reviewing an AI intake request. I also added validation, packaging, release assets, framework mappings, and a live project site to show the project as a complete system rather than a static document repository.

## Questions This Project Can Help Answer

- How do you operationalize governance requirements?
- How do you review change requests for audit readiness?
- How do you evaluate RCA quality?
- How do you identify control evidence gaps?
- How do you approach third-party or AI governance intake?
- How do you map practical workflows to frameworks?
- How do you use AI responsibly in GRC workflows?
